# reports/

Deliverables (markdown reports, CSV/JSON matrices and manifests) from
past research campaigns, grouped by campaign. None of these are read
by the compiler at runtime (`compiler/run_compiler.py` only ever reads
and writes the registry files at the repo root) — they are historical
record, generated by the scripts in `scripts/`.

- `fc005/` — FC-005 (S^3 heat-kernel closure / DESI continuum-limit)
  execution, acquisition, validation, and diagnostic reports.
  `FC005_cosmology.yaml` and `FC005_H3_CORRECTION_TEST_RESULTS.json`
  stay at the repo root instead of here, since
  `compiler/backends/desi_fc005_pipeline.py` and
  `compiler/backends/toe_closure_hypotheses.py` read them directly at
  compiler runtime.
- `l0/` — L0 literature-recovery campaign (baseline manifest, gap
  report, literature index/crosswalks, proposed recovery records).
- `master_theory/` — Master Theory Audit / global certification
  campaign outputs.
- `master_toe/` — Master TOE campaign tables, dependency graph,
  derivation/falsification reports.
- `physics_validation/` — Master Physics Validation Campaign
  (closure/validation matrices, invariant audit, sign-convention
  registry, clean-room reproduction).
- `counterfactual/` — Counterfactual TOE manuscript's reality-gap
  matrix.
- `branch_recovery/` — branch/FC-005 dependency recovery maps.

See the root `README.md` for the compiler itself and which files stay
at repo root because they are part of its I/O contract.
