# Running the Forward-MDCL Compiler + UOC Research Console on macOS

This repository already contains everything needed: the compiler itself
(`compiler/`, `seit_lang/`, `scientific_corpus/`) and a full local web
application on top of it — the **UOC Research Console** (`console/`) — a
FastAPI backend that reads the compiler's real registries live, and a
React/TypeScript frontend with an interactive dependency-graph
visualizer. You don't need to build anything new; you just need it
running on your machine.

**Your M3 MacBook Pro (16GB RAM, 512GB storage) is far more than
enough.** This is a symbolic/numeric compiler (numpy/scipy/sympy) plus a
lightweight local web server and a Vite dev server — not a training
workload. Peak memory use is well under 1GB; the whole checkout plus
Python/Node dependencies takes a few hundred MB of disk.

## What you'll be running

- **The compiler** — `python3 -m compiler.run_compiler` rebuilds every
  canonical registry (objects, transformations, equations, chainlinks,
  protocols, ...), the self-audit report, and the Master Calculation
  Workbook, from source. This is the same command every registry file
  in this repo was generated by.
- **The console** — a local web app at `http://127.0.0.1:5173`:
  - **Backend** (FastAPI, `:8000`): read-only over the compiler's state,
    plus one write route (`POST /api/runs`) that does nothing but invoke
    `compiler.run_compiler.build_and_run()` and report the diff — there
    is no route anywhere that edits a registry directly.
  - **Frontend** (`:5173`): Overview, Registries, an interactive
    dependency graph (Chainlinks), Provenance, Proofs, Falsification,
    Audits, Frontier, Runs (trigger and compare compiler runs from the
    browser), Hypotheses, Literature, Derivation Lab, Theory State, and
    a Node Inspector.

## One-time setup

**Prerequisites** (install via [Homebrew](https://brew.sh) if you don't
have them):

```bash
brew install python@3.12 node git
```

You need **Python 3.11+** and **Node 20+**. Check what you already have
with `python3 --version` and `node --version` — if both already satisfy
that, skip the `brew install` above.

**Get the code.** If you don't already have this repo locally:

```bash
git clone <this-repo-url>
cd SEIT
git checkout claude/forward-mdcl-compiler-build-ng4k2k
```

(If you already have a checkout, just make sure you're on that branch
and up to date: `git fetch && git checkout claude/forward-mdcl-compiler-build-ng4k2k && git pull`.)

**Run the setup script** from the repo root:

```bash
bash scripts/mac_setup.sh
```

This creates a Python virtual environment (`.venv/`), installs the
compiler's and console's Python dependencies into it, and runs
`npm install` inside `console/web`.

> **Why `npm install` is required even if `node_modules` already
> exists:** the frontend's build tool (Vite 8, via Rolldown) and its CSS
> engine (lightningcss) ship platform-specific native binaries. A
> `node_modules` folder built on a different machine (e.g. Linux) will
> not run on macOS — `npm install` fetches the correct
> darwin-arm64 binaries for your M3. The setup script always runs this
> for you; you never need to think about it again after the first run.

## Running it

**Option A — one command, from the terminal:**

```bash
bash scripts/run_console.sh
```

This starts the backend on `:8000`, the frontend dev server on `:5173`
(which proxies `/api` requests to the backend), and opens your browser
to `http://127.0.0.1:5173`. Press `Ctrl+C` to stop both.

**Option B — from VS Code:**

1. Open this folder in VS Code (`code .` from the repo root, or File →
   Open Folder).
2. VS Code will prompt to install the recommended extensions
   (Python + debugpy) — accept that.
3. `Cmd+Shift+P` → **Tasks: Run Task** → **SEIT: Setup (one-time)** (only
   needed the first time, or after pulling dependency changes).
4. `Cmd+Shift+P` → **Tasks: Run Task** → **SEIT: Run Console (backend +
   frontend)**.
5. Open `http://127.0.0.1:5173` in your browser (it should open
   automatically).

Other available tasks (same menu): **SEIT: Backend only**, **SEIT:
Frontend only**, **SEIT: Run Full Compiler** (regenerates every registry
from source, no UI), **SEIT: Run Python Tests** (the full pytest suite —
700+ tests, takes several minutes).

For debugging the backend with breakpoints, use the **Run and Debug**
panel (`Cmd+Shift+D`) and pick **SEIT: Debug Backend (FastAPI)**.

## Using the console

- **Overview** — current state rollup (how many nodes, by status).
- **Registries** — browse the raw object/transformation/equation
  registries.
- **Dependency Graph** (Chainlinks) — the interactive visual graph;
  click any node to open its detail panel (status, provenance,
  dependencies, assumptions).
- **Runs** — click "Run" to actually re-execute the compiler from the
  browser (same as `scripts/run_compiler.sh`) and see exactly what
  changed since the last run.
- **Audits** — the ten self-audit checks (dependency, circularity, type,
  provenance, target-independence, status, leakage-control, numerical
  reproducibility, artifact-completeness, spectral-validation) and their
  pass/fail state.

Everything the console shows is read directly from the same
`*_registry.json` files a fresh `compiler.run_compiler` run produces —
the console never has its own separate notion of state.

## Troubleshooting

- **"No .venv found"** when running a script → run
  `bash scripts/mac_setup.sh` first.
- **Port already in use** (`8000` or `5173`) → something else on your
  machine is using it; stop that process, or edit the port in
  `scripts/run_console.sh` / `console/web/vite.config.ts` (and its
  `proxy.target` if you change the backend port).
- **Frontend fails to start after a `git pull`** → dependencies may have
  changed; re-run `bash scripts/mac_setup.sh` (specifically the
  `npm install` step; it's safe to re-run any time).
- **A native-binary error mentioning `linux` in a `.node` file** → you're
  looking at a `node_modules` copied from a Linux machine instead of
  installed locally. Delete `console/web/node_modules` and re-run
  `bash scripts/mac_setup.sh`.
